# Phase quick Plan 260703-h75: Extract 18 add_* Builders into BuildersMixin Summary

Extracted the 18 `add_*` builder methods from the 95 KB `patcher.py` monolith into a new `BuildersMixin` in `src/maxpat/builders.py` (mirroring the existing `GraphMixin`/`AnalysisMixin` split), annotated the 3 `__init__` methods that genuinely lacked return hints with `-> None`, and stopped re-exporting the private `_AUTO_HIGHLIGHT` from the package — all with zero behavior change (full-suite parity: 2030 passed / 4 xfailed, identical to baseline).

## What Was Built

- **`src/maxpat/builders.py` (new)** — `BuildersMixin` holding exactly the 18 `add_*` methods (`add_box`, `add_comment`, `add_section_header`, `add_subsection`, `add_annotation`, `add_bubble`, `add_panel`, `add_step_marker`, `add_overlay_readout`, `add_labeled_param_bank`, `add_message`, `add_connection`, `add_subpatcher`, `add_bpatcher`, `add_gen`, `add_m4l_gen_synth`, `add_node_script`, `add_js`). All in-method local imports (`calculate_box_size`, `get_bpatcher_dims`, `parse_genexpr_io`/`reorder_genexpr_declarations`, `validate_genexpr`, `warnings`, `re`, `ParamType`/`UnitStyle`/`ModMode`) travel verbatim with the bodies.
- **`src/maxpat/patcher.py`** — the 18 methods removed; `class Patcher(GraphMixin, AnalysisMixin, BuildersMixin)`; `Patchline.__init__`, `Box.__init__`, `Patcher.__init__` annotated `-> None`.
- **`src/maxpat/__init__.py`** — `_AUTO_HIGHLIGHT` dropped from the `aesthetics` import block (was never in `__all__`).

## Circular-Import Handling

`builders.py` needs `Box`/`Patchline` at runtime (17 methods construct `Box`, `add_connection` constructs `Patchline`) and `Patcher` at runtime (3 subpatcher-building methods instantiate it). Resolution:

- The `from src.maxpat.builders import BuildersMixin` line in `patcher.py` was **relocated** from the top mixin-import block to immediately before `class Patcher`, after `Patchline`/`EditResult`/`Box` are defined. At that point `builders.py`'s `from src.maxpat.patcher import Box, Patchline` resolves against the partially-initialized module.
- `Patcher` itself is NOT yet defined at that relocation point, so it cannot be imported at `builders.py` module level. A local `from src.maxpat.patcher import Patcher` was injected into the 3 methods that call `Patcher(...)` (`add_subpatcher`, `add_bpatcher`, `add_gen`) — resolvable at call time when the module is fully loaded.
- Verified robust against direct-first `import src.maxpat.builders` as well as package/patcher-first imports.

- **Issue:** The plan's module-import list named `Any`, the `defaults` constants, and `Box`/`Patchline`, but `add_gen`, `add_node_script`, and `add_js` reference module-global `calculate_box_size` directly (without a local import — unlike `add_comment`/`add_message`/`add_subpatcher`, which import it locally). It was a lowercase global missed by the plan's uppercase-focused scan.
- **Fix:** Added `from src.maxpat.sizing import calculate_box_size` to `builders.py` module-level imports. Confirmed via AST free-name analysis this was the ONLY additional global required.
- **Files modified:** src/maxpat/builders.py
- **Commit:** 2bcfce2

- **Issue:** Same circular-import constraint as above — `Patcher` is unavailable at builders.py module-load time.
- **Fix:** Injected `from src.maxpat.patcher import Patcher` before each `inner = Patcher(...)` site. This is the plan's documented circular-import fallback applied to `Patcher`.
- **Commit:** 2bcfce2
