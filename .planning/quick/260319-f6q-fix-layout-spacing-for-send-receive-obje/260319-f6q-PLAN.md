<objective>
Fix calculate_box_size so width overrides act as a minimum floor, not an absolute cap. When a newobj has a width override from audit data AND the actual text (object name + arguments) would need more width than the override, use the text-based width instead. This prevents layout overlaps for objects like `receive~ mt-glide-freq-sig` where the override (94px) is far too narrow for the argument text (198px needed).

Purpose: Fix layout overlaps for send~/receive~ and any other objects whose argument names exceed the audit-measured width.
Output: Patched sizing.py with tests proving the fix.
</objective>

**Change 1 -- src/maxpat/sizing.py:**

In `calculate_box_size()` at lines 126-135, change the override branch so it computes both the override width AND the text-based width, then returns the larger of the two.

Current code (lines 126-135):
```python
if maxclass == "newobj" and text:
    parts = text.split()
    obj_name = parts[0]
    arg_count = len(parts) - 1
    overrides = _WIDTH_OVERRIDES.get(obj_name)
    if overrides:
        width = overrides.get(str(arg_count)) or overrides.get("default")
        if width:
            return (width, DEFAULT_HEIGHT)
```

Change to:
```python
if maxclass == "newobj" and text:
    parts = text.split()
    obj_name = parts[0]
    arg_count = len(parts) - 1
    overrides = _WIDTH_OVERRIDES.get(obj_name)
    if overrides:
        override_width = overrides.get(str(arg_count)) or overrides.get("default")
        if override_width:
            text_width = len(text) * CHAR_WIDTH + PADDING
            return (max(override_width, text_width), DEFAULT_HEIGHT)
```

The key change: compute `text_width` from the full text, then return `max(override_width, text_width)`. This means:
- Bare objects (cycle~): override wins (68.0 > 58.0) -- keeps audit-measured width
- Long args (receive~ mt-glide-freq-sig): text wins (198.0 > 94.0) -- prevents clipping
- Medium args (cycle~ 440): text wins (86.0 > 68.0) -- correct, "cycle~ 440" needs 86px to display
