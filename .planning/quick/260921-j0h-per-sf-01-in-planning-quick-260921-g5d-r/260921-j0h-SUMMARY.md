# Quick Task 260921-j0h: Close SF-01 — node.script / node.codebox in the object DB

`node.script` and `node.codebox` are now first-class database objects with refpage-verified
fixed 1-in/2-out I/O, and CLAUDE.md no longer bans them from generated patches.

---

## DEVIATION (lead): the task's `variable_io` premise was wrong — fixed I/O implemented instead

The originating SF-01 task text asked to "handle `node.script`'s configurable outlet count via
`variable_io`". **That premise does not survive the evidence, and it was deliberately not
implemented.** Both objects ship as `variable_io: false` with a fixed 1 inlet / 2 outlets, and
**no** `variable_io_rules` entry and **no** new `io_rule` formula were added.

Five independent Max 9.1.5 bundle sources, all read-only (the Max binary was never executed):

| # | Source | Finding |
|---|--------|---------|
| 1 | `node.script.maxref.xml` `<outletlist>` | exactly two `<outlet>` elements, ids 0 and 1 |
| 2 | `node.script.maxref.xml` `<objarglist>` | one argument, `type="symbol"`, `optional="0"` — a **filename**, not a count |
| 3 | `externals/node.script.mxo` string table | attribute strings contain no `outlets` / `numouts` / `nouts` |
| 4 | Cycling '74's own shipped patchers | all 24 `node.script` instances carry `numinlets: 1, numoutlets: 2` |
| 5 | `docs/vignettes/01_n4m_anatomy.maxvig.xml` | names "the left outlet" and "the rightmost outlet" |

The "configurable outlets" phrase traces to *this repo's own* `add_node_script(num_outlets=2)`
builder, not to Max. A rule here would have been actively harmful, not merely redundant: the only
formula that could read arg 0 is `first_arg`, arg 0 is a filename, and
`_warn_non_integer_first_arg` would fire on every lookup; `fixed:2` would misclassify the object
into `audit_empty_io()["variable_io_ok"]`; an invented formula name raises `ValueError` at DB
construction. The verify gate pins the intended behaviour:
`compute_io_counts(n, ['x.js']) == compute_io_counts(n, []) == (1, 2)`.

CLAUDE.md bullet 7 was corrected from "configurable outlets" to the verified fixed shape as part
of the same change, so the stale claim does not survive anywhere in the repo's live rules.

## Other Deviations from Plan

### 1. [Rule 3 — blocking] `sort_keys=True` would have rewritten all 471 entries

- **Found during:** Task 1
- **Issue:** The plan's action step said to dump the JSON with `sort_keys=True, indent=2`, then
  "diff to confirm the only changed lines are the two new blocks." These two instructions
  contradict each other. The on-disk file stores **per-object** keys in extractor order
  (`name, maxclass, module, domain, category, digest, description, inlets, …`), not
  alphabetically. Verified empirically before writing anything:
  `json.dumps(raw, indent=2, ensure_ascii=False) + "\n"` round-trips **byte-identical** to the
  current file, while `sort_keys=True` does not.
- **Fix:** Dumped with `sort_keys=False` and sorted only the **top-level** keys explicitly
  (`{k: raw[k] for k in sorted(raw)}`). The plan's actual intent — strict key sort order at the
  top level — is preserved and still asserted by the verify gate (`list(raw) == sorted(raw)`).
- **Files modified:** `.claude/max-objects/max/objects.json`
- **Commit:** `65e662e`

## Follow-Ups (recorded, deliberately not implemented here)

1. **`add_node_script(num_outlets=N)` for `N != 2` emits a box MAX will not honor.** The real
   object always creates 2 outlets. Fixing it (routing through `Box()`/the DB) would break
   `tests/test_codegen.py:623-630`, which currently asserts the 3-outlet form — so the fix needs
   its own test coverage and its own task.
2. **`node.codebox` and `v8.codebox` are candidates for `UI_MAXCLASSES` admission.** The shipped
   `node.codebox` help-patch box is stored as `maxclass: "node.codebox"` with a `code` attribute
   and no `text` — the same evidence class that admitted `codebox` in quick task 260921-ima.
   Today `Patcher().add_box('node.codebox')` still emits `maxclass: "newobj"` (confirmed at
   verify time). Needs its own MAX-saved-form evidence pass. Note `v8.codebox` is already in the
   same state, so this task leaves a pre-existing inconsistency intact rather than creating one.
3. **Bundle-verified but refpage-undocumented attributes were omitted** per settled decision S4:
   `options` (both objects — present in the `node.script` binary string table and in two shipped
   help-patch box texts, e.g. `@options --experimental-modules`, `@options --inspect-brk=9229`)
   and `code` (`node.codebox`'s stored JavaScript). Adding them needs an evidence-recording
   convention that `max/objects.json` does not have — its complete field set across all entries
   is exactly `arguments, attributes, category, description, digest, domain, inlets, maxclass,
   messages, min_version, module, name, outlets, rnbo_compatible, seealso, tags, variable_io,
   verified`, with no `_audit` / `_note` / `source` / `evidence` key anywhere.
4. **`.claude/max-objects/extraction-log.json` still reports the pre-task counts by design**
   (S6). It is a timestamped artifact of the 2026-07-01 extraction run; hand-editing it would
   make it disagree with its own `extraction_timestamp`, and tests only assert `> 1500`.

Also left untouched per S6: `patches/psycography/context.md` and `patches/barnett-dbap/context.md`
(historical rationale and a recorded user decision D24, SF-04 precedent).
