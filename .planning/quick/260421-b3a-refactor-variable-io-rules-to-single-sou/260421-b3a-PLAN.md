# Refactor variable_io rules to single source of truth

**Scope:** REVIEW-260420-j15 FN-01 (move rules out of extract_objects.py), FN-02 (avoid double-parsing overrides.json), DQ-02 (delete inline `io_rule` fields).

**Out of scope (deferred):**
- routepass / o.route formula judgment (DQ-02 judgment items)
- mc.pack~ / mc.unpack~ variable_io flagging (DQ-07)
- arg_count empty-args semantics (FN-03 — already shipped in 260420-lla)
- first_arg non-integer warning (FN-04 — already shipped in 260420-lla)

## Gray areas already settled

| Decision | Choice | Why |
|----------|--------|-----|
| Conflict resolution on duplicate objects | **overrides.json wins** | overrides.json is already the runtime source for `db_lookup`; the extract_objects dict was unused at runtime. |
| Formula name normalization | `arg_count_plus_1` → `arg_count+1`, `first_arg_plus_1` → `first_arg+1` | Match what `_apply_io_formula` accepts — the `_plus_1` variants silently fell back to `default`. |
| `bpatcher` special formula `inherited_from_subpatch` | **Allow in supported set** | Currently silently falls back to `default` in `_apply_io_formula`; preserving semantics. Document in validator. |
| Test target | `pytest tests/test_db_lookup.py -x -q` (22 baseline + 2 new = 24 expected) | Keep existing + add regression + negative validation. |
