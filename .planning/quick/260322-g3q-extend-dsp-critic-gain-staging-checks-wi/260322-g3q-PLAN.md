  <action>
    1. In `_check_unsafe_gain_sources`, the backward BFS already traces through arbitrary control objects. The issue is `line~` is a signal-rate object (name ends with ~), so:
       - It connects to *~ inlet 1 via a SIGNAL connection (line~ outlet is "signal")
       - The current code only traces CONTROL connections backward, so line~ is invisible

    2. Add `line~` awareness: After finding *~ (and mc.*~) boxes, also check for signal predecessors on inlet 1 that are `line~`. Build a small signal predecessor map (dst_id, dst_inlet) -> list of src_ids for signal connections. If line~ feeds *~ inlet 1 via signal, trace backward from line~'s control inputs using the existing ctrl_backward map.

    3. For message boxes feeding line~: parse the message text. Per project memory (feedback_line_tilde_comma.md), line~ uses a single flat list for multi-segment envelopes -- NO commas. Format is: `target1 time1 target2 time2 ...` as one message. A simple two-value message is `target time` (e.g., "0.5 500"). Multi-segment is `target time target time` (e.g., "0.8 10 0. 500"). Parse by splitting on whitespace. Values at even indices (0, 2, 4...) are target values, odd indices are times. If ANY target value > 1.0, flag as blocker. A single number with no time (e.g., "0.5") is also a valid target -- check it too.

    4. For non-message control sources feeding line~ (like ctlin, number, etc.): apply the same MIDI-range source + normalizer logic already in the BFS. Essentially, when line~ is detected as a signal feeder to *~ gain inlet, treat line~'s control inputs as if they directly feed the gain inlet.
