  Run a one-off Python audit from the repo root using the installed `ObjectDatabase`. Do not write a permanent script; use `python -c "..."` or a scratch `.py` in the quick-task directory (then delete). Capture these measurements directly into REVIEW.md:

  1. **Per-domain counts** — for each of `max, msp, jitter, mc, gen, m4l, rnbo`, plus total packages:
     - total object count (entries in the raw JSON)
     - count with empty inlets AND empty outlets
     - count with empty inlets only
     - count with empty outlets only
     - count with `rnbo_compatible: true`
     - count with `variable_io: true`
  2. **Baseline comparison** — test file header claims ~130 critical empty-I/O entries. Call `db.audit_empty_io()` and report current `critical` / `covered_by_override` / `variable_io_ok` sizes. Note the delta vs 130 and attribute it to the recent milestones (quick-260419-vy7 populated 11 entries).
  3. **Outlet-type correctness for mixed-outlet MSP objects** — sample ~10 MSP objects where outlets of different types are expected (e.g., `snapshot~`, `thresh~`, `buffer~`, `peek~`, `index~`, `record~`, `sfplay~`, `sfrecord~`, `groove~`, `play~`). For each, check `db.get_outlet_types(name)` matches the documented MAX behavior. Flag mismatches.
  4. **Cross-domain duplicates** — find names that appear in multiple per-domain JSON files. Report each duplicate with the domains it appears in and whether the schemas agree (inlet count, outlet count, rnbo_compatible). Flag mismatches; note which domain wins under `DOMAIN_LOAD_ORDER`.
  5. **PD blocklist completeness** — check whether any PD-only names NOT in `pd-blocklist.json` appear in the per-domain files. Focus on common PD confusions known from CLAUDE.md (the ones listed AND: `pd`, `loadbang` [exists in both — verify], `clip~` [already flagged as both-exist], `receive~`/`send~` [MAX has these — not PD-only], `delread~`, `delwrite~`, `expr~` [exists in both]). Cross-reference each PD blocklist entry against `db._objects` — if a PD-blocklisted name ALSO exists as a real MAX object and the blocklist entry doesn't mention it, flag as ambiguous.
  6. **`rnbo_compatible` consistency** — for the RNBO-only domain file (`rnbo/objects.json`), verify every entry has `rnbo_compatible: true`. For the core domains, spot-check 10 well-known RNBO-compatible objects (e.g., `cycle~`, `+~`, `*~`, `biquad~`, `line~`, `scale`, `pack`, `unpack`, `metro`, `select`) and 5 known NOT-RNBO objects (e.g., `buffer~` [it IS rnbo], `coll`, `dict`, `js`, `node.script`) — report any incorrect flags.
  7. **`variable_io` coverage** — list every object with `variable_io: true` across all domains, and check whether each has a matching entry in `overrides.json` → `variable_io_rules`. Missing rules = silent bug in `compute_io_counts`. Also spot-check objects that *should* be variable but might not be flagged: `trigger`, `pack`, `unpack`, `route`, `sel`, `gate`, `switch`, `router`, `matrix~`, `mc.pack~`, `mc.unpack~`, `mc.unpack`, `mc.*`.
  8. **Alias resolution sample** — for each of the 12 aliases in `aliases.json`, call `db.lookup(alias)` and verify the canonical target exists. Flag any dangling alias.
  9. **Overrides precedence** — pick 3 objects with overrides (e.g., `+`, `*`, `-`) and confirm that `db.lookup(name)` returns values matching the overrides JSON, not the raw per-domain data. Also verify `db.is_overridden(name)` returns `True` for those.
  10. **db_lookup.py functional audit** — walk each public method and identify:
      - boundary/edge-case bugs (e.g., `_apply_io_formula` returning `default` when `args` is empty — is that correct for every formula? `first_arg` with non-integer first arg silently returns `default`, which could mask a malformed patch)
      - `get_outlet_types` when `num_outlets > len(db_outlets)`: it inherits from the last outlet — is that right for `trigger` (all outlets control, inherits control, fine) vs `route` (last outlet is the unmatched, different type)?
      - `compute_io_counts` when `variable_io: true` but no rules entry: falls back to defaults (len of empty arrays = 0, 0). Silent bug? Compare against which objects this actually affects from step 7.
      - Any method that silently swallows exceptions or returns sentinels that a caller might misinterpret
      - Performance: `audit_empty_io()` iterates all objects — O(N). Fine. But `_load` reloads `overrides.json` twice (variable_io_rules, then objects). Minor, flag as cosmetic.
  11. **Test coverage gaps** — cross-reference `tests/test_db_lookup.py` against public methods. List which methods have zero tests (likely `compute_io_counts`, `get_outlet_types`, `is_pd_object`, `get_pd_equivalent`, `list_packages`, `get_package_objects`, `is_core`, `get_package`, `get_package_info`, `is_overridden` — verify). Recommend test additions by priority.
