    - Test: A cord routing around an obstacle uses midpoints that stay outside the obstacle's bounding box (with COLLISION_PAD margin)
    - Test: Existing midpoint tests (horizontal offset, bus routing, companion, manual preserved) still pass
  </behavior>
  <action>
    Add obstacle avoidance to `_generate_midpoints()` in layout.py. The core algorithm:

    1. Add a helper `_boxes_between(patcher, src_box, dst_box) -> list[Box]` that finds boxes whose vertical span (y to y+h) overlaps with the cord's vertical range AND whose horizontal span overlaps with the cord's horizontal corridor. These are potential obstacles.

    2. For "normal_lines" (the forward-flowing, horizontally-offset cables that currently get simple L-shaped midpoints), add obstacle detection BEFORE generating midpoints:

       For each normal line with `hdist > HORIZONTAL_THRESHOLD`:
       a. Compute the straight-line corridor from (src_ox, src_oy) to (dst_ix, dst_iy).
       b. Find all boxes whose bounding rect (expanded by COLLISION_PAD=5.0) intersects this corridor.
       c. Exclude src_box and dst_box themselves from obstacle set.
       d. If NO obstacles: use existing L-shaped midpoint at vertical midpoint (unchanged behavior).
       e. If obstacles exist: route AROUND them. Strategy:
          - Sort obstacles by y position (top to bottom).
          - For each obstacle, determine if the cord should go LEFT or RIGHT around it. Choose the side with more space (compare obstacle center-x to cord corridor center-x). If obstacle center is right of corridor center, route left of obstacle; otherwise route right.
          - Generate midpoints that step around each obstacle: go to the obstacle's edge (left or right, + COLLISION_PAD), then vertically past it, then back toward the destination.
          - Simplify: for the common case of 1 obstacle, generate a 4-midpoint dog-leg: (src_ox, pre_obstacle_y) -> (route_x, pre_obstacle_y) -> (route_x, post_obstacle_y) -> (dst_ix, post_obstacle_y) where route_x is the obstacle's left or right edge +/- COLLISION_PAD, and pre/post are obstacle top-COLLISION_PAD and obstacle bottom+COLLISION_PAD.

    3. For near-vertical cables (`hdist <= HORIZONTAL_THRESHOLD`), also check for obstacles in the vertical path. If an obstacle blocks a straight vertical cable, add a small horizontal jog around it (same left/right logic).

    4. Import COLLISION_PAD from the existing codebase. Check if it's already defined (it was mentioned in STATE.md decisions: "COLLISION_PAD = 5.0px"). If not in defaults.py, add it there: `COLLISION_PAD = 5.0`.

    5. Do NOT change upward bus routing or companion routing -- those already route along specific paths and don't have the straight-through-object problem.

    6. Add tests to test_layout.py in a new `TestObstacleAvoidance` class:
       - `test_cord_avoids_intermediate_object`: Create 3 rows of objects where a cord from row 0 to row 2 would cross through a row 1 object. Verify the cord gets midpoints that don't intersect the row 1 object's bounding box.
       - `test_no_obstacle_unchanged`: Create 2 rows with a horizontal offset cord but no obstacle in the path. Verify behavior matches existing (simple L-shape midpoints or none).
       - `test_vertical_cord_avoids_offset_obstacle`: Place an obstacle slightly offset from a vertical cord path. Verify the cord routes around it.
  </action>

    - Test: Each returned candidate has >= min_group_size (default 3) boxes
    - Test: UI objects (toggle, slider, dial, etc.) are excluded from subpatcher candidates (they're user-facing)
    - Test: suggest_subpatchers() returns list of dicts with keys: boxes (list[str] of box IDs), name (str), external_ins (int), external_outs (int)
  </behavior>
  <action>
    Add `suggest_subpatchers(patcher, min_group_size=3, max_external_connections=3) -> list[dict]` to layout.py (or a new section at the bottom of layout.py).

    Algorithm:
    1. Build undirected adjacency graph from patcher.lines (same as _find_components).
    2. Exclude UI objects (name in _UI_CONTROL_NAMES or is_ui_object()) and "ezdac~"/"ezadc~"/"dac~"/"adc~" (I/O objects that should stay top-level).
    3. Find connected subgraphs in the filtered graph.
    4. For each subgraph with >= min_group_size boxes:
       a. Count external connections: connections where one end is in the subgraph and the other is NOT.
       b. If external connections <= max_external_connections, this is a candidate.
       c. Auto-name the subgraph using SECTION_SIGNATURES from analysis.py (import it) -- look for the highest-priority signature object in the group.
    5. Return list of candidate dicts: `{"boxes": [box_ids], "name": suggested_name, "external_ins": count, "external_outs": count}`.

    This is a SUGGESTION function -- it does NOT automatically create subpatchers. Agents call it to decide whether to group objects. The function is purely analytical.

    Add tests in a new `TestSubpatcherSuggestion` class in test_layout.py.
