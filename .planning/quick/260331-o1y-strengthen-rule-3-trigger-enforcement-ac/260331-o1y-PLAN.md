  <action>
Add a new section to shared-capabilities.md titled "## Control-Rate Fan-Out Rule (MUST)" after the existing "## Z-Order Manipulation" section (before "## Aesthetic Capabilities").

The section MUST contain:

1. A one-line rule statement: "When a control-rate outlet connects to 2+ destinations, you MUST use a `trigger` (t) object. Direct multi-connect from one outlet to multiple inlets is NEVER acceptable for control-rate connections."

2. A note that signal-rate (~) connections are exempt -- MSP signal fan-out is safe because all signal inlets process simultaneously at audio rate.

3. A before/after example using ASCII art showing:

**WRONG -- direct fan-out (undefined execution order):**
```
[button]
  |  \
  |   \
  v    v
[counter] [toggle]
```
The outlet of button connects to both counter inlet 0 and toggle inlet 0. Execution order is undefined -- MAX may fire them in any order.

**RIGHT -- trigger for explicit ordering:**
```
[button]
  |
  v
[t b b]
  |   \
  v    v
[counter] [toggle]
```
trigger fires right-to-left: toggle gets bang first, then counter. Order is explicit and predictable.

4. A note that the structure critic (`src/maxpat/critics/structure_critic.py`) detects fan-out without trigger and flags it. Agents must not produce patterns that trigger this finding.

5. A reminder: "This applies to ALL control-rate fan-out, even when execution order 'does not matter.' Always use trigger -- no exceptions for control-rate."
  </action>
