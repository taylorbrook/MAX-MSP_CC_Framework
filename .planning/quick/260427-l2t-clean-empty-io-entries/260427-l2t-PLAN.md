Drop the ObjectDatabase critical empty-I/O bucket from 130 to under 20 by:

1. **Pass A — Blacklist 4 documentation-page non-objects.** These are extractor false-positives caught by scraping `.maxref.xml` heading text rather than real `<object>` entries. Delete them from their per-domain objects.json files. They are NOT real Max objects.

2. **Pass B — Auto-extract package object I/O via help-file scan.** Build a one-shot helper at `tools/extract_pkg_io.py` that opens each `_pkg-source/<pkg>/help/<obj>.maxhelp` JSON file, finds the target object instance by text-prefix match, and reads its `numinlets`/`numoutlets`/`outlettype` fields. The 4 doc-page entries are nonsense (`maxref.xml` headings extracted as objects). The 126 real package objects need I/O so patches using them validate correctly.

Output: ~120 new override entries, 4 fewer DB entries, 1 new test, 1 new tool script.
