    ```python
    def _validate_package_gating(
        patch_dict: dict, db: ObjectDatabase, allowed_packages: list[str] | None
    ) -> list[ValidationResult]:
        """Check that no objects from non-allowed packages appear in the patch.

        This is defense-in-depth: Patcher-level gating should catch these during
        generation, but this catches violations in loaded/edited patches.
        """
        if allowed_packages is None:
            return []  # No package config -- skip check

        results = []
        for box_entry in patch_dict["patcher"]["boxes"]:
            box = box_entry.get("box", {})
            name = _extract_object_name(box)
            if name is None:
                continue
            package = db.get_package(name)
            if package and package not in allowed_packages:
                results.append(ValidationResult(
                    "packages", "error",
                    f"Object '{name}' from package '{package}' not in allowed packages "
                    f"(allowed: {allowed_packages})",
                ))
        return results
    ```

    # Layer 2c: Package gating
    results.extend(_validate_package_gating(patch_dict, db, allowed_packages))

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-03 | Tampering | allowed_packages bypass | mitigate | Box.__init__ receives allowed_packages explicitly from Patcher -- no global state. If Patcher is constructed without it, filtering is disabled (None = allow all), maintaining backward compat without creating a bypass. Defense-in-depth validation catches any objects that slip through. |
| T-22-04 | Elevation of Privilege | from_dict() bypass | accept | from_dict() deliberately skips Box.__init__ (uses __new__) to load existing patches without gating. This is correct design -- you should be able to load any patch. Validation catches issues post-load if allowed_packages is provided. |
